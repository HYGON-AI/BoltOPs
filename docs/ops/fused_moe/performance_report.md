# Fused MoE 性能报告：BoltOPs vs Aiter

> 测试时间：2026-09-06。本轮在 BMZ25 和 NMZ27 显式加载 `/zhenxin/triton3-moe-gemm1-opt` 的 `d2d4cc362079590b93a16acae41fbe6ff30425ad`，基于 `/zhenxin/BoltOPs` 的 `b0dc1ae8a336b40a259602075149b84c1a248b2b`，在两台机器上用 8 卡并行重新实测报告保留的全部 9 个 case。

> 本轮 BoltOPs HEAD 为 `b0dc1ae8a336b40a259602075149b84c1a248b2b`：先 cherry-pick `b67e520`，再 cherry-pick `b0dc1ae`。回归在 BMZ/gfx936 与 NMZ/gfx938 均为 `189 passed, 3 skipped`。

> 当前 Triton 包含 review 后的 8-wave BPP 扩展，BoltOPs 包含 large-M Triton 3.6 配置重训结果。BPP 候选只有在 GEMM1 胜出，并且 GEMM2 使用相同 `BLOCK_SIZE_M` 后的总时间仍胜出时才写入 config；默认 chunk 维持 32768。

本报告按机器整理：BMZ 5 个 case，NMZ 4 个 case；每个 case 覆盖 M=1、2、4、8、16、24、32、64、128、256、512、1024、2048、4096、8192、16384、32768。
其中 M=32768 使用新的默认 chunk=32768，其余 M 的执行口径不受该默认值变化影响。

测试 shape 取自 Aiter `op_tests/ci_tests` 的 fused-MoE 用例；Aiter backend 查询、weight shuffle 与 `aiter_moe` 调用沿用 CI 路径。为了做成同输入的成对性能比较，报告 harness 生成一次真实 `fused_topk` routing，并同时交给 BoltOPs、ASM、ASM Shuffle 和 HIPC/MOE_C；CUDA Graph 只计 kernel，预处理与 shuffle 不计时。

NMZ 容器使用 Torch 2.9，而指定 wheel 标记为 Torch 2.10；为避免替换 NMZ 的 Torch，本轮从该 wheel 自带源码一次性 JIT 重建了与 Torch 2.9 ABI 兼容的 Aiter 扩展，native config、CSV 与 HSACO 仍来自同一指定 wheel。BMZ 直接使用 wheel 的预编译扩展。

正提升表示 BoltOPs 更快，公式为 `(Aiter - BoltOPs) / BoltOPs * 100%`。ASM、ASM Shuffle、HIPC/MOE_C 分列展示；只要 provider 实际执行并返回有效时长就纳入性能统计，正确性诊断保留在原始 JSON 中，不用于隐藏可运行 provider。
Aiter 的 block-wise MOE_C generic fallback 不符合 block-scale GEMM 语义，因此只保留在原始 JSON 作诊断，不纳入报告性能列。


## Aiter native backend 支持概览（当前 wheel）

Aiter 先按数据/量化类型和 channel-wise/block-wise 布局选择 backend，再按 GPU 架构、E/N/K、topk 和 M 查找 native config。下表的“支持*”表示存在该 backend 路径，不保证报告中的每个具体 shape 都有 config。

| 数据类型 | 量化/布局 | ASM（原始权重） | ASM Shuffle Weight | HIPC/MOE_C | MOE_C 权重布局 |
|---|---|---:|---:|---:|---|
| BF16 | W16A16 | 支持* | 支持*（独立 shuffle CSV） | 支持* | 强制预 Shuffle，无 non-shuffle 版本 |
| INT8 | W8A8 channel-wise | 支持* | 支持*（独立 shuffle CSV） | 支持* | 强制预 Shuffle，无 non-shuffle 版本 |
| FP8 | W8A8 channel-wise | 支持* | 支持*（独立 shuffle CSV） | 支持* | 强制预 Shuffle，无 non-shuffle 版本 |
| FP8 | W8A8 block [128,128] | 支持* | 支持*（独立 shuffle CSV） | 当前 wheel 的 block-wise 策略不支持 | — |

ASM 与 ASM Shuffle 使用独立 solution table。HIPC/MOE_C 只有预 Shuffle 口径；报告不包含 INT4。
